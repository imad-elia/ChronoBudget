# Session — 2026-07-27 (later still, part 2)

## Summary

Follow-up to [[2026-07-27f-session]] (savings goals). The user asked whether the automated test suite covers what's needed for App Store / Play Store submission. Ran an audit via an Explore agent, then — since the user wanted concrete gaps addressed rather than just a report — filled in the missing config, privacy manifest, and store-listing metadata that were blocking a native build or submission.

## What was done

### Audit
An Explore agent read `app.json`, checked for `eas.json` (didn't exist), read `.github/workflows/ci.yml`, checked `vault/Architecture/testing-strategy.md` and the 2026-07-03 iOS verification session, searched for any store metadata/privacy-policy files, and searched the whole app for network calls/analytics. Findings:
- CI (`test` + `e2e` jobs, both `ubuntu-latest`) only ever exercises the **web** build via Jest + Playwright — zero native iOS/Android build, simulator, or device step exists anywhere in the pipeline. Expected: automated tests validate logic, not store compliance.
- `app.json` was missing `android.package`, `android.versionCode`, and `ios.buildNumber`.
- No `eas.json` existed at all — no way to produce a store-ready native binary.
- No iOS privacy manifest (`PrivacyInfo.xcprivacy` / `ios.privacyManifests`) — Apple has required this since 2024 for apps using "required reason" APIs, which `expo-file-system` (CSV export/import) triggers.
- No privacy policy or store-listing metadata anywhere in the repo (no `fastlane/`, `store-assets/`, `metadata/`).
- Confirmed the app is genuinely offline: no `fetch`/network calls, no analytics/crash-reporting SDKs, no backend anywhere in the code (only two harmless Expo-docs URLs in comments/JSX text).
- The 2026-07-03 iOS Simulator "verification" was a one-time manual check via a macOS VM, not automated — no equivalent Android check found.

### Fixes applied
- **`app.json`**: added `android.package: "com.imadelia.chronobudget"` (mirrors the iOS bundle identifier) + `android.versionCode: 1`; added `ios.buildNumber: "1"`; added `ios.privacyManifests` declaring exactly two "required reason" categories — `NSPrivacyAccessedAPICategoryFileTimestamp` (`C617.1`) and `NSPrivacyAccessedAPICategoryDiskSpace` (`E174.1`) — scoped to `expo-file-system`'s actual usage in `lib/csv.ts`/bulk import, not over-declared.
- **`eas.json`** (new): `development`/`preview`/`production` build profiles + a `submit.production` skeleton. `ios` submit config left empty deliberately (no fabricated Apple ID/ASC App ID/team ID — `eas submit` prompts interactively). `android` submit config points at `./google-service-account.json`, which doesn't exist yet and is now gitignored.
- **`.gitignore`**: added `google-service-account.json` alongside the existing `*.jks`/`*.p8`/`*.p12`/`*.key` secret patterns.
- **`docs/privacy-policy.html`** (new): static page intended for GitHub Pages (`/docs` on `main`). Content accurate to the actual code: no accounts, no data collection, no network calls, local-only storage, CSV export/import as the only file-system touchpoint. Has a `TODO: add contact email` placeholder.
- **`store-assets/metadata/en-US/{short_description,full_description,keywords,release_notes}.txt`** (new): draft listing copy in the standard fastlane/EAS-submit layout, based on the app's real current feature set. `store-assets/README.md` documents what's explicitly out of scope (screenshots, real contact email).

- Explicitly could not and did not attempt: an actual `eas build`/`eas submit` run (requires the user's own Apple Developer/Google Play accounts and real credentials), or generating screenshots (requires a real device/simulator capture).
