## Decisions made

- `jest-expo` (Expo's own preset) over a hand-rolled Jest config — avoids fighting SDK 56's transform requirements.
- `sql.js` (pure-JS `sql-asm.js` build, not the default WASM build) to mock `expo-sqlite` in tests, so DB logic runs against real SQL instead of hand-stubbed fakes. WASM build was tried first and rejected — see Problems below.
- Web E2E via Playwright over native Detox/Maestro — runs on `ubuntu-latest` with no simulator/emulator/macOS-runner infrastructure, consistent with how the rest of the suite runs; native E2E stays a documented non-goal for now.
- `npm audit fix` (non-force) applied for the 3 fixable advisories; the `uuid` advisory deliberately left unfixed since forcing it downgrades `expo` and would break the SDK 56 setup this whole project depends on.
- `actions/checkout` and `actions/setup-node` bumped to `v5` (not just the `node-version` input) to actually clear the runner's Node 20 deprecation warning.

## Problems encountered

- Hand-copied `transformIgnorePatterns` override broke `expo-modules-core` parsing — removed the override, trusted jest-expo's own default.
- `@testing-library/react-native` v14's `render()` **and** `fireEvent.*` are both async — omitting `await` on either caused cryptic failures (unbound `screen` singleton; stale form state read before a state update flushed) and React "overlapping act()" warnings. Fixed by awaiting every call.
- `sql.js`'s default WASM build throws an empty, unhelpful `Error` from `new SQL.Database()` under Jest — a known Jest/WebAssembly incompatibility (each test file runs in its own `vm` context; V8 WASM instances don't cross realms correctly). Switched to the `sql-asm.js` (pure JS, no WASM) build.
- Pushing Phase 2 revealed 4 pre-existing TypeScript errors that had never blocked anything before CI started running `tsc --noEmit` — all behavior-preserving fixes (see open-issues.md for the list).
- Jest's default `testMatch` picked up `e2e/*.spec.ts`, and Playwright's `test()` throws when run inside Jest — fixed via `testPathIgnorePatterns`.
- Playwright's `getByText()` substring-matches by default (unlike RNTL) — caused a false-ambiguous match; fixed with `{ exact: true }`. Also has no `getByDisplayValue()` equivalent — worked around with a `testID` + `toHaveValue()`.
- A real flake in the E2E transactions spec: reopening the edit modal immediately after Save occasionally raced the modal's close animation, producing a transient duplicate text match. Fixed by waiting for the modal to be confirmed closed before reopening it, rather than adding an arbitrary sleep.
- The GitHub Actions HTML page returned stale/cached content across several manual status checks this session — the REST API (`api.github.com/.../actions/runs`) was the reliable way to confirm run status; WebFetch's own 15-minute cache also needed a cache-busting query param at one point to get fresh data.
