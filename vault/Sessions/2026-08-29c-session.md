# Session — 2026-08-29 (c)

## Summary

Third session of the day, following [[2026-08-29b-session]]. The user asked whether any of the 190 manual cases in the release test plan could be automated. Answer: about 105, of which ~85 need no native harness. They chose Tiers 1 + 2 (data layer, CI matrix, static checks, web E2E — no Maestro) and both AST lint checks.

Implemented in five phases, each verified and committed separately. Test count went 157 → 188 unit tests plus 3 → 16 Playwright specs, with a new `checks` CI job and a three-timezone matrix on the existing `test` job.

The most valuable findings were not the new tests but two defects in the test infrastructure itself, and a live app bug the first static check caught on its first run.

## What was done

### Phase A — the harness blind spot

`__mocks__/expo-sqlite.ts` implemented `withTransactionAsync` as `await callback()`. No BEGIN, no COMMIT, no ROLLBACK — so every assertion in the suite about money moving "atomically" was really asserting statement order.

Fixing it appeared not to work, which turned out to be the more serious problem: jest-haste-map had found two manual mocks named `expo-sqlite` (the project's, and a copy under `.claude/worktrees/exciting-bose-b67c07/`) and was resolving the **worktree's**. The DB suite had never run against the project's own mock. Fixed with `modulePathIgnorePatterns` rather than deleting the worktree, which is the user's to remove. That also cleared the long-standing parallel-worker timeouts — the suite went from six failing suites in 24s to clean in 7s.

Once real transactions were in play, all 157 existing tests still passed: the behaviour was correct, it simply had no coverage. Added a rollback regression test that exploits the ordering inside `insertTransfer` — the source account is debited before the transfer row insert fails on its foreign key, so without a real ROLLBACK the debit survives and money vanishes.

### Phase B — data-layer coverage (+30 tests)

New `db/__tests__/migrations.test.ts` seeds a populated DB at each shipped schema version (v3–v7) from frozen DDL snapshots and migrates it forward, asserting v8 with no data lost, plus a guard that the destructive v1 block never runs against a DB already at v1+. The existing suite only ever migrated a *fresh* database, so the path every real device takes on upgrade was completely untested. Mutation-checked by disabling the v8 migration and confirming red.

Also: clock edges (two-year forward jump, backward clock, DST, late-night month boundary), a money-column validation audit, float-drift and precision robustness, and CSV variants (CRLF, BOM, accents, quoted commas).

### Phase C — CI timezone matrix

Spiked first, as the plan required. Both assumptions held: sql.js resolves `localtime` through Emscripten, which derives its offset from JS `Date`, so an in-process timezone reaches the SQL layer.

Proved by deliberate failure: with the morning's `localtime` fix reverted, the UTC job still passes while Auckland fails 58 vs 100 — exactly the misbucketed first-of-month transaction. The `test` job now runs in UTC, Pacific/Auckland and America/Los_Angeles.

### Phase D — four static checks

`scripts/`, run via `npm run check` as its own CI job. Written against the TypeScript compiler API and executed by Node 24's native type stripping, so no new dependency.

`check-frozen-i18n` found a **seventh** live instance of the frozen-label bug on its first run: `RecurringModal`'s `FREQUENCY_LABEL` froze the Weekly/Monthly/Yearly labels in the rule list, with the correct keys-only pattern sitting three lines above it in the same file. Fixed.

`check-contrast` found that `textMuted` fails WCAG AA — 2.51:1 on sheets, 2.25:1 on cards. Left as a decision rather than a fix (see below).

### Phase E — five Playwright specs

`language.spec.ts` is the important one: it switches to French once and then visits every surface *without reloading*, because a reload masks exactly the bug it hunts. Plus onboarding navigation, fast input, accounts/goals, and a zero-external-request assertion.

### Verification

Final state: **188 unit tests across 15 suites**, passing in all three timezones (default UTC+2, Pacific/Auckland, America/Los_Angeles); **16 Playwright specs** across 8 files; `npx tsc --noEmit` clean; `npm run check` clean apart from the two baselined contrast warnings.

New coverage was proved able to fail rather than assumed correct: the migration ladder was mutation-checked by disabling the v8 block, and the timezone matrix by reverting the morning's `localtime` fix.

### Vault correction

The project note's testing bullet claimed the stray worktree was "pre-existing environment noise, not a real regression". That was wrong — it was silently winning mock resolution — so the claim was corrected rather than left standing beside the new entry.

## Decisions made

- **Hard-fail with a documented allowlist, not warn-only.** The plan proposed starting `check-hardcoded-strings` as a warning until existing violations were cleared. All six violations turned out to be Expo template scaffolding, so instead the three files are allowlisted with reasons and the check hard-fails on anything new in product code. A warning in CI is a warning nobody reads.
- **Baseline the contrast failures visibly rather than fix or suppress them.** Raising `textMuted` changes the calm, low-glare look the OLED palette exists for, which is a product call. The two known pairs report as warnings on every run, and if either later passes the check *fails* until the marker is removed, so it returns to being protected.
- **`CB_TZ`, not `TZ`.** Under Git Bash on Windows, MSYS intercepts `TZ`, so neither the env prefix nor `export` reaches node.exe. `CB_TZ` passes through everywhere and `jest.globalSetup.js` applies it before workers fork.
- **Guard the worktree in Jest config rather than deleting it.** It is the user's directory and may hold work; `modulePathIgnorePatterns` solves the problem without touching it.
- **Dropped goal tagging from the E2E.** Driving the chip picker through the web renderer added selector churn without adding coverage over the SQL-level tests. Stays manual as GOAL-02 / GOAL-06, recorded in the spec itself.

## Problems encountered

- **Heredocs are unusable for this content.** Bash heredocs repeatedly truncated or mangled TypeScript containing apostrophes, backticks and SQL-injection test strings; backticks inside double-quoted `node -e` strings also became command substitution and corrupted a vault note (reverted with `git checkout`, then redone by writing the content to a file and inserting it with a script reading from that file). Use file-based writes for anything with mixed quoting.
- **Playwright selector churn.** Four separate rounds: `getByText` is substring *and* case-insensitive by default; RN Web keeps closed `Modal`s mounted so text matches in several sheets at once; `getByDisplayValue` does not exist; `AccountsModal` and `GoalsModal` list views have no Done control and close on a backdrop tap. All now recorded in [[testing-strategy]].
- **One unreproduced parallel-run failure**, logged under "Watch" in [[open-issues]] rather than dismissed.
