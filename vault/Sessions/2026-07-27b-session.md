**Feature 1 — French locale + i18n fixes.**
- Fixed the frozen module-scope `t()` bug in `SettingsModal.tsx`, `OnboardingOverlay.tsx`, and `KeywordsModal.tsx`: each computed a `CATEGORY_LABEL`/`BALANCE_CATEGORIES` array via `t()` once at import time. Replaced with a `StringKey`-only map (e.g. `CATEGORY_LABEL_KEY = { needs: 'category.needs', … } as const`) evaluated via `t()` at render time instead.
- Added a reactivity fix to `KeywordsModal.tsx`: it was the only `t()`-calling component subscribed to no locale-linked store field at all (only `learnedKeywords`), so it wouldn't re-render on a locale change while open. Added a no-op `useBudgetStore((s) => s.symbol)` subscription, matching the pattern every other locale-aware screen already used.
- Routed ~15 previously-hardcoded strings through `t()`: `BentoCard.tsx`'s "OVER" badge, `OnboardingOverlay.tsx`'s tour Back/Next/Got it/Skip buttons, `trends.tsx`/`history.tsx`/`index.tsx` screen titles, empty states, and the budget-limits modal — plus category names that were baked directly into `BENTO_CONFIG`/`CATEGORY_CONFIG`/`FILTERS` module constants in `index.tsx`/`history.tsx`/`trends.tsx` instead of looked up via `t('category.*')` (a duplication risk the initial plan hadn't itemized, caught while implementing since it would have left category names in English even after switching locale). Reused existing duplicate keys (`history.title`, `trends.title`, `history.empty`, `edit.cancel`) instead of creating near-duplicates.
- Added `constants/i18n/fr.ts` (full French translation, mirrors every `StringKey`) and registered it in `lib/i18n.ts`'s `BUNDLES`.
- **Found live during browser verification**: a fourth instance of the same frozen-`t()` bug in `ExpenseInput.tsx` (`CATEGORY_LABEL` computed at module scope) — missed by the initial scoping pass. Confirmed by seeing "NEEDS" instead of "BESOINS" in the smart-input category preview after switching to French. Fixed with the same pattern as the other three.
- New `lib/__tests__/i18n.test.ts` (locale resolution, prefix matching, fallback chain, interpolation) and a new `KeywordsModal` test asserting labels update when the store's locale-linked field changes while the modal is mounted.

**Feature 2 — Fuzzy/stemming matching.** All changes confined to `lib/detectCategory.ts`, no new dependency:
- `detectCategory` is now a two-pass token scan: pass 1 is the original exact lookup (learned map then `KEYWORD_MAP`, first token wins); pass 2 (fuzzy fallback) only runs if pass 1 found nothing, scanning the same tokens in the same order against a stemmed exact lookup (`stemCandidates`: handles consonant+y plurals, -ing forms that dropped a silent e, and plain -s/-es plurals) then a bounded Levenshtein scan (`withinLevenshtein`: distance ≤1 for tokens ≤5 chars, ≤2 for longer; tokens under 3 chars skip fuzzy matching entirely).
- Because pass 1 always completes before pass 2 runs, an exact match on a later token always beats a fuzzy match on an earlier one.
- Fuzzy hits set `matched: true` (same as exact), so they are not auto-learned into `keyword_learn` unless the user overrides — reuses the existing `overridden || !matched` learn-trigger in `ExpenseInput.tsx` with no changes needed there.
- New tests in `lib/__tests__/detectCategory.test.ts` covering stemming (plural, -ing), Levenshtein typo correction, precedence (exact-beats-fuzzy across tokens), learned-map-beats-seed-map for fuzzy candidates, a far-off non-match still falling through, and the short-token guard.

## Decisions made

- Language stays derived from country selection only this session — no independent language-selector UI (user's explicit choice, matches the existing documented design in [[localization]]).
- `Detection`'s interface stays unchanged — fuzzy hits are indistinguishable from exact hits to callers, no `matchType`/`fuzzy` field added (user's explicit choice, minimizes surface area per CLAUDE.md's anti-over-abstraction guidance).
- Fuzzy hits are never auto-learned into `keyword_learn`, even though they set `matched: true` — avoids polluting the learned table with possible false positives from a distance-2 Levenshtein match; relies on the fuzzy matcher catching the same input again next time instead.
- Category-name duplication across `BENTO_CONFIG`/`CATEGORY_CONFIG`/`FILTERS`/`CATEGORIES` (hardcoded "Needs"/"Wants"/"Savings" module constants in 3 files) was brought into scope mid-implementation even though the original plan didn't itemize every occurrence — leaving it would have meant category names stayed in English even with French selected, undermining the feature's actual goal.
- The hardcoded `$` bug found in `LimitsModal` (`index.tsx`) was deliberately *not* fixed inline — it's a currency-symbol correctness bug, not a translation issue, and out of the approved plan's scope. Flagged via a spawned background task instead.
