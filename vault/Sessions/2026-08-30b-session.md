## What was done

1. **CSV export hardcoded to English.** `app/(tabs)/history.tsx`'s `handleExport` built the header row and category cell as literal English strings, with a hardcoded native share-dialog title too. Fixed via new `csv.header.*` and `history.exportDialogTitle` i18n keys, reusing the existing `category.*` keys for the category cell. Date/time cells deliberately stay in a fixed, locale-independent format — `lib/csv.ts:parseCsv` reconstructs the timestamp from those cells, so they can't be locale-formatted without breaking round-trip parsing. To keep a French export importable, `lib/csv.ts` now recognizes both locales' header row and category labels, by importing `constants/i18n/en.ts`/`fr.ts` directly rather than hand-duplicating strings.
2. **Dashboard Recent-list dates hardcoded to `en-US`.** `app/(tabs)/index.tsx`'s `TransactionRow` now reads `locale` via a reactive store selector (not `.getState()`, to avoid the frozen-value bug class already fixed elsewhere in this project) and passes it into the existing `toLocaleDateString` call.
3. **Over-limit display.** `components/BentoCard.tsx` now shows the OVER badge plus a plain `"$spent / $limit"` text line instead of a bar + uncapped percentage once spending exceeds the limit — a product call from the user, not a bug fix. `components/ProgressBar.tsx` (also used by `GoalsModal.tsx`) is untouched; the branch lives entirely in `BentoCard.tsx`.
4. **Large-amount truncation.** `adjustsFontSizeToFit` is iOS-only and does nothing on React Native Web, so long formatted amounts got clipped by `numberOfLines={1}` at a fixed 32px. Replaced with a small `amountFontSize()` helper that picks a smaller font size by the formatted string's length — works identically on web and native.
5. **Trends compact-currency grouping.** `lib/format.ts:formatCompactCurrency` divided by 1000 and appended `k` without re-applying thousands grouping to the quotient. Fixed by reusing the file's existing `grouped()` helper and capitalizing to `K`, matching the user's expected output exactly (no new "M" tier — the reported example is still meant to read in thousands).
6. **Custom subcategory not remembered.** `ExpenseInput.tsx`'s subcategory chips came from a static constant; a typed custom value saved correctly on the transaction itself but was never written anywhere the chip row could read it back from. Added `customSubcategories` state to `store/useBudgetStore.ts` (cached-from-SQLite pattern, same shape as `learnedKeywords`), persisted via the existing generic `getSetting`/`setSetting` app_settings helpers — no schema migration. Loaded at app-mount; `ExpenseInput.tsx` now concatenates the static list with the per-category custom list and calls `addCustomSubcategory()` on submit. Noted but not fixed: `EditTransactionModal.tsx`/`RecurringModal.tsx` have their own separate static chip lists with the same latent gap — out of scope for this report.
7. **DET-04 lookup.** Not a code issue — retrieved directly from the "ChronoBudget Release Test Plan" claude.ai artifact (not stored in the repo): *"Account tagging debits the account atomically"* (Checking 1200 → 1150 after a tagged 50 transaction).

## Decisions made
- Keep CSV date/time cells in a fixed, non-localized format rather than locale-formatting them — round-trip parsing correctness took priority over the (untested) assumption that the user wanted the date *values* themselves translated, versus just the header/category labels.
- Compact-currency fix keeps a single "K" (thousands) scale rather than introducing an "M" tier, following the user's own literal expected-output example rather than inventing a new format not asked for.
- Left `EditTransactionModal.tsx`/`RecurringModal.tsx`'s parallel custom-subcategory gap unfixed — flagged as a known extension rather than silently expanding scope beyond the reported bug.
