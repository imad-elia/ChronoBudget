# Session — 2026-07-27 (late)

## Summary

Implemented all three remaining roadmap items from [[ChronoBudget]]'s "Next steps" in one planned, four-phase pass: a French keyword dictionary for the smart-input classifier, an independent language selector, account-aware budgeting (accounts + transfers), and CSV round-trip import. Worked from a plan approved via plan mode; each phase ended with `tsc --noEmit` + full `npm test` before moving to the next.

## What was done

### Phase 1 — French keyword dictionary
- Added `constants/keywords/fr.ts` (~250 entries), registered in `constants/keywords/index.ts`.
- `constants/keywordMap.ts` changed from a frozen `KEYWORD_MAP` constant (computed once at import time, hardcoded to `'en'`) to a live `getActiveKeywordMap()` accessor that reads the current language on every call — the seam the codebase had already flagged as "per-language-ready" but never wired up.
- `lib/i18n.ts` gained `getActiveLocale()` so other modules can read the active language without depending on the store.
- `lib/detectCategory.ts`: split the English-only suffix stemmer into `stemCandidatesEn`/`stemCandidatesFr`, selected by active locale; added `stripDiacritics()` (NFD + combining-mark strip) so accented input ("café") matches the unaccented dictionary keys used in `fr.ts`.
- Tests: 6 new cases in `lib/__tests__/detectCategory.test.ts` covering French seed matches, accent-insensitive matching, French stemming, and amount+description parsing.

### Phase 2 — Independent language selector
- `store/useBudgetStore.ts`: new `language: SupportedLanguage` field (`SUPPORTED_LANGUAGES = ['en', 'fr']`, i.e. only locales with a real translation + keyword bundle), `setLanguage()` action persisted via `app_settings` key `language`. `setCountry()` now only sets a default language when none has ever been explicitly saved (checked via `getSetting('language')`), so a later country/currency change doesn't silently override an explicit language pick.
- New keys `settings.language`/`settings.languageHint` in `en.ts`/`fr.ts`; a picker (English/Français, native-language labels) added to `SettingsModal.tsx` below the country list.
- See [[localization]] for the full design writeup.

### Phase 3 — Account-aware budgeting (accounts + transfers)
- Schema **v7**: `accounts` table, `transfers` table, nullable `account_id` FK added to `transactions` and `recurring`. Full design rationale (why a dedicated table instead of extending `category_balance`, why transfers are a separate table rather than a 4th category value) in the new [[account-aware-budgeting]] decision note.
- `db/database.ts`: `fetchAccounts`/`insertAccount`/`updateAccount`/`deleteAccount` (refuses to delete an account still referenced by a transaction/recurring rule), `fetchTransfers`/`insertTransfer` (atomic two-account balance update + record insert). `insertTransaction`/`updateTransaction`/`deleteTransaction` now keep an account's `balance` in sync atomically (`withTransactionAsync`) when a transaction carries an `account_id`.
- New `components/AccountsModal.tsx` (list/add/edit/delete accounts, plus a transfer sub-flow), reachable from `SettingsModal.tsx`.
- Optional account-tag chips added to `ExpenseInput.tsx` and `EditTransactionModal.tsx` — hidden entirely when no accounts exist, so users who never set one up see no UI change.
- Tests: 12 new `db/__tests__/database.test.ts` cases (schema table list, account CRUD, balance math on insert/update/delete, delete-blocked guard, transfer atomicity, transfers excluded from category totals).

### Phase 4 — CSV round-trip import
- New `lib/csv.ts`: `parseCsv()` reverses the existing export transform (`Date,Time,Category,Subcategory,Note,Amount`) via a small quoted-field-aware line splitter. Malformed rows (wrong field count, bad date, non-positive/non-numeric amount) are skipped and counted rather than aborting the whole import. A missing/invalid Category cell falls back to `detectCategory()` on the Note text.
- `db/database.ts`: `insertTransactionsBulk()` wraps all rows in one `withTransactionAsync`.
- `app/(tabs)/history.tsx`: import button added next to Export. Web uses a plain `<input type="file">` + `Blob.text()`; native required adding **`expo-document-picker`** (the one new dependency this whole plan needed — no in-repo alternative existed for native file selection) alongside the already-present `expo-file-system`. Result summary shown via `Alert.alert`.
- Tests: 8 new `lib/__tests__/csv.test.ts` cases (well-formed round-trip, quote-escaping, missing header tolerance, per-row-type skip counting, classifier fallback), plus 2 `insertTransactionsBulk` cases in `db/__tests__/database.test.ts`.

## Decisions made

- [[account-aware-budgeting]] — new decision note: dedicated `accounts`/`transfers` tables instead of extending `category_balance`'s pattern; transfers as a separate table rather than a 4th `category` enum value.
- [[localization]] updated in place — independent language selector section added, stale "no independent language-selector UI was added" scope note corrected.
- CSV import stays deliberately round-trip-only (confirmed with the user before implementation) rather than generic bank-CSV import with column mapping — the latter would be a much larger, separately-scoped feature.
- Accounts scope confirmed as "full accounts + transfers" (not just named balances) before implementation.
