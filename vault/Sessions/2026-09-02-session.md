## Summary

User made a manual edit to `components/BentoCard.tsx` + `constants/i18n/en.ts`/`fr.ts` outside of Claude Code, then asked for it to be logged and reviewed.

## What changed (user's manual edit)

The over-balance badge (wallet icon) now uses a new `card.overby` key ("OVER BY $X") instead of reusing `card.over` ("OVER $X"), which stays on the over-limit badge (speedometer icon) unchanged. `en.ts`/`fr.ts` both got the new key ("OVER BY" / "DÉPASSÉ DE"). Also a harmless import-ordering/formatting cleanup at the top of `BentoCard.tsx` (no behavior change).

## Review verdict: good change

Yesterday's balance-vs-limit disambiguation fix ([[2026-08-30d-session]]) gave both badges identical `"OVER $X"` wording, but `$X` meant different things per badge: for the limit badge, `$X` is the limit itself (you're over your $50 limit — correct to show as-is); for the balance badge, `$X` was `Math.abs(remaining)`, i.e. the *overspend amount*, not the balance. So "OVER $70.00" on the balance badge read as if $70 were the balance, when it was actually how far past it you were. This manual fix disambiguates by giving the balance badge its own "OVER BY $X" wording, which correctly frames the number as an overage amount. Icons still carry the wallet-vs-speedometer distinction on top of this.

## Fixed to keep it green

The new wording broke 2 pre-existing assertions in `components/__tests__/BentoCard.test.tsx` that still expected the old shared `"OVER $20.00"` text for the balance case. Updated both to `"OVER BY $20.00"`.

## Part 2: large-amount overflow on phone-width BentoCards

User reported testing on a real Samsung S26 Ultra: once spend/limit/balance amounts pass roughly $10K, the OVER badges and the balance "remaining" line on the Needs/Wants/Savings cards don't display fully — the 3-column card grid leaves each card only ~115dp wide on a real device, and those text lines had no auto-shrink (unlike the main amount, which already had a length-based font-size helper for exactly this reason). Asked for UX proposals; used `AskUserQuestion` with four options (compact+tap-to-expand / tap-only / compact-only / responsive stacked layout) — user picked the combined **compact text + tap-to-expand** option.

### What was done
1. **Compact large amounts on the card itself.** New `displayAmount()` helper in `components/BentoCard.tsx`: once `Math.abs(amount) >= 10000`, switches to the existing `formatCompactCurrency()` ("$12.3K") instead of `formatCurrency()`. Applied to the main amount, the balance remaining line, and both OVER badges. Below $10K, unchanged. Reuses `formatCompactCurrency()` (already used by Trends' chart axis labels) — no new formatting logic.
2. **Tap a card to see exact figures.** `BentoCard` gained optional `onPress`/`testID` props; when `onPress` is passed it renders as a `TouchableOpacity` (was always a plain `View`). New `components/BentoCardDetailModal.tsx` — a bottom sheet matching the existing `GoalsModal`/`AccountsModal` visual pattern — shows unabbreviated numbers: spent, limit + real (uncapped) percentage + a `ProgressBar`, starting balance + remaining, and an explicit "OVER BY $X" line for either kind of overage. Wired into `app/(tabs)/index.tsx`'s `DashboardHeader` via a `detailCategory` state field, one modal instance shared across the three cards.
3. New i18n keys `card.spent`/`card.limit`/`card.balance`/`card.used` added to `en.ts`/`fr.ts`, following the existing `card.*` naming convention.

### Testing
- Extended `components/__tests__/BentoCard.test.tsx`: compact-threshold cases for the main amount, remaining line, and both badges; `onPress` firing on tap; falls back to non-interactive when `onPress` is omitted.
- New `components/__tests__/BentoCardDetailModal.test.tsx`: exact (never-compacted) figures for balance-only, limit-only, both together, over-balance, and over-limit cases; backdrop/Done-button close.
- `npx tsc --noEmit`, `npm run check`, `npm test` — all clean, 214/214 tests passing.
- **No browser or manual testing performed this round** — per explicit instruction, the user is verifying directly on their own S26 Ultra device rather than through token-costly browser automation.
